# Adversarial accessibility review: DESIGN.md and EXPERIENCE.md

Reviewed 2026-09-29. Scope: `DESIGN.md`, `EXPERIENCE.md` against `apps/web/src` (DiscoveryMatrix, CardTile, CardDetailModal, DescriptionEditor, BoardToolbar, RootLayout, story-map-shell, stores, `styles/global.css`), PRD NFR-5 (WCAG 2.1 AA for core flows) and epics Story 6.10, 6.3, 6.7, 3.10, 5.4. Contrast values are sRGB relative-luminance ratios computed with the WCAG formula (script kept in the session scratchpad, not in the repo).

## Verdict

**Not ready to hand to story writers as the accessibility contract.** The philosophy is right: state carried by word plus icon plus shape, a Move dialog as the equal of drag, a table twin for the Graph, a live-region idea, `Esc` as topmost-layer close. The Floor, however, is a list of intentions. Read literally, and combined with the ratified CSS, it lets these ship while every automated check stays green:

1. No specified focus-indicator system. The code has zero `:focus-visible` rules, and the spine reuses the focus token for "selected" (indistinguishable) and fails 3:1 on the rail.
2. A roving-focus grid whose tiles contain 7 to 10 nested controls, with `Enter`, `Space` and `Delete` bound twice (tile versus popover, checkbox, dnd-kit handle, text inputs) and a global `/` shortcut that fails WCAG 2.1.4 (Level A).
3. Focus loss on every move, delete and live update, because tiles re-mount when their parent cell changes.
4. Modal, confirm-dialog and Esc handling that Story 6.7 says "trap and restore" but that does not exist today and is under-specified (deep link, removed opener, stacked dialogs, destructive default focus).
5. Live announcement that covers only agent changes, not the user's own moves, errors or saves, and has no coalescing rule to test.
6. Card color category (and priority) still carried by a bare swatch on the tile.
7. Story 6.10 as written cannot fail: `apps/web` has no DOM test environment (no jsdom, no browser runner), and `--passWithNoTests` passes empty suites. Color-contrast, target-size, focus and zoom are not checkable in jsdom.

Several claims about the existing UI are wrong (baseline keyboard handling, zoom range, "most already have names"), so stories built on them will under-scope.

Counts: **Critical 6, High 9, Medium 10, Low 5** (30 findings).

## Critical

### C-1. No focus-indicator system; selection, drop-over and focus share one token; rail and filled buttons fail 3:1
- **Where:** DESIGN.md Colors (`focus-ring`) and Components > Card tile ("selected tile shows a 2px focus-ring outline with a 2px offset"); EXPERIENCE.md Floor bullet 3; `global.css` 459-462, 1336-1337, 1579, 1608.
- **Problem:** (a) The code has no focus styling at all; `.tiptap` removes the outline, so the description editor has no visible focus (2.4.7). (b) "Selected" and "focused" are drawn with the same 2px `#3D7C59` ring, and `.droppable-over` uses the same color dashed. A keyboard user cannot tell which tile is focused from which is open in the modal or from which is drag target. (c) Ratios above: 2.999 on chrome, 2.08 on the active rail item, 1.49 against primary fill. (d) Sticky Activity and Step rows plus pinned lanes (up to 240px each) can cover the focused tile when the roving grid scrolls it into view (2.4.11 Focus Not Obscured, 2.2 AA).
- **Fix:** Add to DESIGN.md an explicit focus token set: `focus-ring-on-light: #2D5F45` (7.41 on white, 5.94 on activity tint, 6.92 on step tint), `focus-ring-on-dark: #FFFFFF` (10.34 on `chrome-hover`, 14.91 on chrome), always `outline: 2px solid` with `outline-offset: 2px` (never `box-shadow` alone, it disappears in forced colors), plus a 2px white halo on tinted tiles. One global `:focus-visible` rule; forbid `outline: none` without a replacement (stylelint `declaration-property-value-disallowed-list`). Rename the selection style: bulk selection = checkbox checked plus 3px left bar plus `aria-selected`; keep focus ring exclusive to focus. Card modal open state gets a distinct "current" mark. Add `scroll-padding-top` and `scroll-padding-bottom` equal to sticky header plus pinned lane heights on `.discovery-matrix-scroll` and require the grid's focus routine to `scrollIntoView({block:"nearest"})` after that padding exists. AC: "Every focusable element, on every surface color in DESIGN.md, has a focus indicator of at least 2px with at least 3:1 against both adjacent colors; never fully covered by sticky elements at 200 percent browser zoom."

### C-2. Roving-focus grid is undefined where it collides with everything inside a tile
- **Where:** EXPERIENCE.md Interaction Primitives > Keyboard, Component Patterns > Card tile, Card color popover, Bulk action bar; `CardTile.tsx` 60-249; `DiscoveryMatrix.tsx` 315, 665-683.
- **Problem:**
  - A discovery tile has 7 to 10 focusable controls (checkbox, left, right, park, restore, delete, content button, swatch, priority, drag handle). The spec never says whether those stay tab stops. With 1,000 Cards that is up to 10,000 stops; if they are removed, color, priority, park, restore, per-tile delete confirmation and ticket links have no keyboard path at all (the Move dialog covers only position and Release).
  - `Enter` is bound to "open Card" on the tile and to "open popover" on the swatch (Card color popover row). `Space` is bound to "toggle bulk selection", while native buttons and the checkbox activate on Space and the dnd-kit handle picks up on Space or Enter. A container-level `keydown` handler will double-fire.
  - The handler must not act when the event target is an `<input>`: the `AddControl` inputs, lane rename input, Search, the story title composer all sit inside the grid or next to it. Typing "m" in "New story…" must not open the Move dialog; `Delete` and `Backspace` in a text field must not open delete.
  - `Delete` acts on the focused tile or on the selected set? Unstated ("Space toggles selection, Delete asks to delete"). With 5 selected and focus on a sixth, the outcome is untestable and destructive.
  - The two-dimensional traversal is unspecified: a cell holds a vertical stack of Stories, the grid has variable-height cells, add-cells, collapsed lanes (`display:none`), a pinned lane and Not assigned. What do `ArrowUp` past the top of a stack, `Home`, `End`, `PageUp`, `Ctrl+Home` do? Does focus enter lane headers, add buttons, lane controls?
  - dnd-kit's default `KeyboardSensor` stays wired; its default coordinate getter on a 2D grid inside a CSS-zoomed container is not usable and duplicates the Move dialog.
- **Fix:** Specify the APG grid pattern with actionable cells. One tab stop for the whole grid (`tabindex="0"` on the current tile, `-1` on the rest). The tile primary action (its content button) is the roving element: `Enter` opens the Card; `Space` toggles selection; `Tab` while a tile is focused moves through that tile's secondary controls only (all other tiles' secondary controls `tabindex=-1`), and `Tab` past the last one leaves the grid; `Esc` inside a tile control returns to the tile. Bind keys only when `event.target` is the tile itself (`event.target === event.currentTarget`), never for events from inputs, selects, editors, buttons. `Delete`: acts on the focused tile only, unless exactly the selected set contains the focused tile, then on all selected, and the dialog names the count. Define arrows: Left/Right across columns within the same lane, Up/Down through the stack then into the previous or next lane; `Home`/`End` row ends; `Ctrl+Home`/`Ctrl+End` grid ends; `PageUp`/`PageDown` lane. Skip `display:none` lanes; add-cells and lane headers are reachable by Tab (they are controls, not cells). Remove the tile's drag handle from the tab order (`tabIndex={-1}`, `aria-hidden`) and set `sensors={[PointerSensor]}` so drag is pointer-only and the Move dialog is the keyboard path. Add a per-tile "Edit fields" entry (or reuse Card modal) for color and priority. Rewrite epics Story 6.3 baseline line.

### C-3. Focus is lost whenever the focused tile re-mounts, moves or disappears (own edits and live updates)
- **Where:** EXPERIENCE.md Interaction Primitives > Live updates, Move dialog; State Patterns > Agent changed something; `DiscoveryMatrix.tsx` (`DiscoveryCell` per `cell:${step.id}:${release}`; `key={story.id}` under different parent), `CardTile.tsx` (`SortableCardTile`).
- **Problem:** Moving a Story to another Release or Step changes its parent cell, so React unmounts the tile and mounts a new one; focus falls to `<body>`. This happens for the Move dialog itself (dialog closes, focus returns to an opener that no longer exists), park, delete, archive, filter changes, lane collapse of the lane holding focus, and agent-driven moves within 2 seconds while a keyboard or screen-reader user is on the tile. The spine says "focus returns to the opener on close" only for the Card modal and says nothing else.
- **Fix:** Add a "Focus continuity" rule to the Floor and implement one mechanism: every tile has `data-card-id`; before an operation that can re-mount, record the focused id; after commit, in a layout effect, focus the tile with that id in its new place. If it no longer exists (deleted, filtered out, archived, now collapsed), focus the next sibling in prior grid order, else the previous, else the grid container with an `aria-label`. Announce the result through the status region ("Moved K-12 to Release 2, position 3"). For live updates, do not move focus but keep the focused tile stable: if the focused tile would move or disappear, apply the data change and retain a placeholder of the focused tile until blur (or show "1 change waiting for the card you are on") rather than pulling it away. AC: "After Move dialog confirm, focus is on the moved tile's new element; after delete, focus is on the next sibling, else the grid."

### C-4. Modal and confirm-dialog focus handling is not implemented and the spine leaves the hard cases open
- **Where:** EXPERIENCE.md Component Patterns > Card modal, Confirm dialog, State Patterns > Restore in progress; Floor bullet 3; `CardDetailModal.tsx` 146-161, 199-201, 322-334; `DiscoveryMatrix.tsx` 513-565 (custom dialogs), 119 and 126 (`window.confirm`).
- **Problem:**
  - Today: no initial focus, no trap, no `inert` background (so the rail, header and board stay in the tab order and the virtual cursor), no restore. Esc is a `window` listener; with the "unsaved changes" dialog open it re-sets the same state instead of cancelling it, contradicting "`Esc` closes the topmost layer". The three Discovery dialogs have no `role`, `aria-modal`, label, Esc handling or focus management, and their buttons are three equal destructive choices with no default.
  - Spec gaps: which element gets initial focus in the (long, scrolling) Card modal; what "opener" means on a `?card=<id>` deep link, after reload, after the opener re-mounted or moved (C-3), or when closed by browser Back (closure comes from routing, not from the close button); stacked dialogs (unsaved-changes over Card modal, conflict over modal) order and Esc; dialogs must not start with the destructive button focused; Enter must not confirm a delete when focus is on it by default; the non-dismissible "Restoring" modal has no focusable child, so focus placement and announcement are undefined; the "Save state" footer is not a live region.
- **Fix:** Build all dialogs on the native `<dialog>` with `showModal()` (built-in focus containment, inert background, Esc, top-layer stacking), or one shared `Dialog` component doing the same. Rules to write into the Floor: initial focus = the dialog heading (`tabindex=-1`) for the Card modal, the least destructive button for `role="alertdialog"` confirms (`autofocus` on Cancel); confirm dialogs have `aria-labelledby` (title) and `aria-describedby` (consequence sentence); `Esc` closes only the topmost dialog and cancels a confirm; closing (any cause, including Back) restores focus to the recorded opener element if still connected, else to the tile with the same `data-card-id`, else to the grid; the "Restoring" modal is `role="alertdialog"` with the sentence as description and focus on its container; save state is `role="status"`. Replace `window.confirm` in DiscoveryMatrix (lines 119, 126) in the same story as the dialog component; the 3-way "where should child cards go" choice becomes radio buttons plus one confirm button named with the verb. AC: "With the Card modal open, Tab and Shift+Tab never reach an element outside it; after close by Esc, close button and Back, `document.activeElement` is the opener or the documented fallback."

### C-5. Announcement model covers only agent changes; no coalescing rule; own actions and errors are silent
- **Where:** EXPERIENCE.md Floor bullet 4, State Patterns (Agent changed something, Live stream reconnecting, Agent protection on toast, Changes panel), Interaction Primitives > Live updates; epics 3.10 (100 ms invalidation coalescing is a data rule, not an announcement rule); `RootLayout.tsx` 189.
- **Problem:** WCAG 4.1.3 (AA in 2.1) requires status messages for the user's own actions too: "Moved K-12 to Release 2", "Saved", "Delete failed", "3 selected", "No cards match", filter counts ("N matches / M cards" is a plain `<span>` today), bulk result, conflict callouts, sync results. The spec announces only "3 cards changed by Claude Code". Undefined: coalescing window, max frequency, message format, when the region is mounted (a region injected together with its text is not announced), what happens to a toast ("Claude Code proposed 12 changes. Review.") that auto-dismisses (2.2.1), who is announced during reconnect flapping, whether the existing `role="alert" aria-live="polite"` contradiction (line 189) is fixed, and how a screen-reader user reaches the changed cards afterwards.
- **Fix:** One always-mounted `role="status"` (polite, `aria-atomic="true"`) region in `RootLayout` for statuses and one `role="alert"` region for errors and conflicts. Rules: aggregate per actor over a 1.5 s trailing window, at most one message per 5 s, max 120 characters, format `"{N} cards changed by {actor}. Open What changed to review."`; never announce the user's own event echo; Reconnecting is silent for 30 s, then the alert. Own-action statuses in past tense with the object name. Toasts: minimum 10 s, pause on hover and focus, dismissible, and every toast's content persists in the What changed panel or Activity badge. Counts in the header (cards, releases, matches) sit in a `role="status"` container only for the matches count. AC: "A 30-operation agent change produces exactly one status message within 5 s; a keyboard move produces one message naming the card and destination; errors use the alert region."

### C-6. Card color categories and priority remain color-only on the tile, with a generic accessible name
- **Where:** DESIGN.md Colors ("Card color categories ... small swatch"), Do's and Don'ts; EXPERIENCE.md Card color popover; `CardTile.tsx` 129-158, `card-visual-options.ts`; `global.css` 513-521, 556-571.
- **Problem:** The spine adds a text label "in the popover, on the Card modal and in filters" but not on the tile, where the swatch is the only carrier. That fails 1.4.1 (A) for sighted users who cannot tell the hues and 1.4.11 (yellow 1.46:1, Risiko 2.03:1, Standard white 1.85:1 via border). The palette collapses in grayscale (pairs at 1.03 to 1.14). The swatch's accessible name is "Farbkategorie wählen" with no current value, so a screen-reader user cannot read the category at all on the board; popover options carry names but no selected state. Priority "has-priority" is white on orange 2.03:1 and its name ("Priorität wählen") omits the value. Notably `BoardToolbar` also exposes a free hex input ("Color #fff7df") that bypasses categories.
- **Fix:** Make the swatch a chip with a per-category glyph (distinct shapes: square, triangle, diamond, circle, hexagon, plus letter or numeral for Team 1 to 4) and the label text at 12px on Discovery tiles at zoom 100 percent (glyph only below that, with the name in the accessible name). Set the swatch button name to `"Color: Blocker. Change color"` (`aria-haspopup="listbox"`, `aria-expanded`), popover as `role="listbox"` with `aria-selected`. Priority button name `"Priority 2. Change priority"`; text color `#18201D` on the orange or a dark-on-light badge (`#18201D` on `#f5a623`: computes above 7). Remove the hex input from the bulk bar or replace with the category select. Add to DESIGN.md a rule "swatch border at least 3:1 against tile" or, better, drop the border and use the glyph outline in `text`.

## High

### H-1. Single-character global shortcut `/` fails WCAG 2.1.4 (Level A); `m` needs its scope written down
- **Where:** EXPERIENCE.md Interaction Primitives > Keyboard ("`/` focuses search. No other global shortcuts").
- **Problem:** 2.1.4 forbids letter, punctuation, number and symbol shortcuts unless they can be turned off, remapped, or are active only while a specific component has focus. `/` is global. `m` is acceptable only because the spec ties it to a focused tile, but nothing says so. Also `/` collides with typing in inputs and the rich-text editor.
- **Fix:** Remove `/` or make it `Alt+/`-style with a modifier; if kept, add a "Keyboard shortcuts" setting (off switch) per Story. State that `m` (and any later single key) is active only while the grid has focus and never from text controls. Add the 2.1.4 criterion to the Floor.

### H-2. Input, select and secondary-button boundaries are 1.51:1 and the spine ratifies the token
- **Where:** DESIGN.md `border-strong`, `button-secondary`; `global.css` 1640-1650 (all `input, select, textarea`), `.description-editor`.
- **Problem:** 1.4.11 requires 3:1 for the visual information needed to identify a form control. Text inputs have no other affordance, so 1.51 fails on every form in the product. axe does not test this; Story 6.10 would pass.
- **Fix:** Add `border-input: #7A877F` (3.75 on white, 3.64 on `#FBFCFA`, 3.49 on `#F6F7F4`, 3.37 on lane-alt `#EEF3FB`); use it for inputs, selects, textareas, the editor frame and unfilled checkbox and chip boundaries. Secondary buttons keep text `primary` (7.41) and may keep `border-strong`. Add "form-control boundary at least 3:1 against every surface it appears on" to the Floor.

### H-3. Reflow and responsive statements contradict the 2.1 AA target
- **Where:** EXPERIENCE.md Responsive & Platform ("below 768px not a target, untested"), Floor bullet 9; DESIGN.md Layout ("Phones are not a target"); `global.css` 2790-2812 (only breakpoint 980), 1536 (Card modal fixed 330px column), 25 (rail 248px).
- **Problem:** 1.4.10 Reflow (AA) requires content to work at 320 CSS px width (400 percent zoom at 1280 px) without two-dimensional scrolling, except for the board itself, tables, maps and diagrams. Zooming to 400 percent on a laptop produces a 320px viewport; "not a target" is therefore not available. The Floor tests only 200 percent ("must not cut off controls"), which is 1.4.4, not 1.4.10. Current CSS at ≤980px turns the rail into a sticky horizontal scroller (nav scrolls sideways = 2D scroll of non-exempt content; about 90 px of a 512 px viewport at 200 percent is consumed by the sticky bar); the spine's "rail collapses to icons" is a different design and needs icon names and tooltips; the Card modal's 330px column alone exceeds 320px.
- **Fix:** Replace the phone sentence with: "Every non-board surface reflows to 320 CSS px; the Discovery board, Tree and Graph canvas are exempt as two-dimensional content, but their toolbars, Card modal, dialogs, drawers and panels are not." Specify the narrow behavior: rail becomes a disclosure menu (button named "Menu", not a sticky bar), Card modal and panels single column below 720px, dialogs `max-width:100%`. Test at 1280x1024 with browser zoom 200 and 400 percent, and at 320x256.

### H-4. Discovery board uses CSS `zoom`: targets and text scale down, sticky offsets and dnd-kit coordinates are engine-dependent, and the slider is mis-specified
- **Where:** DESIGN.md Layout & Spacing ("zoom scales the board never the chrome"); EXPERIENCE.md Floor bullet 9 ("Discovery zoom is independent"); `global.css` 739-744 (`zoom: var(--discovery-zoom)`), 766-773 (sticky `top: var(--discovery-activity-h)` from `offsetHeight`); `DiscoveryMatrix.tsx` 175-192, 567-577 (`transform.x / zoom`); `RootLayout.tsx` 156-168.
- **Problem:** (a) At the 0.5 minimum, 12px meta text renders at 6px and the 22px icon buttons at 11px (see H-5). (b) The board is intentionally horizontal-scrolling (exempt from reflow) but the sticky rows, `ResizeObserver` heights and dnd-kit rects are measured in different coordinate spaces depending on engine and version (standardized `zoom` changed `getBoundingClientRect` and `offsetHeight` behavior in Chromium; Firefox only shipped `zoom` in 126). The code compensates only for the drag transform (`/ zoom`). A wrong sticky offset can leave an overlap or gap that hides the focused tile (2.4.11). (c) The maximum is 125 percent, so the in-app control cannot magnify at all beyond that; low-vision users depend on browser zoom, and the Floor gives no test for browser zoom combined with the board zoom (1.25 x 2.0). (d) The zoom range input has no `aria-valuetext` ("100 percent"), the wrapper `<div aria-label="Discovery zoom controls">` has no role, and `step=0.01` gives 76 stops per direction on arrow keys.
- **Fix:** Either replace `zoom` with a CSS variable applied to sizes (`--u: calc(1rem * var(--discovery-zoom))` and `em` units inside the board) so layout, sticky measurements and rects share one space, or keep `zoom` and require a cross-engine test (Chromium, Firefox, WebKit) of drag, sticky offsets and focus scroll at 50, 100 and 125 percent. Raise the minimum to 0.75 or define an "overview mode" below 0.75 that hides all secondary tile controls (keyboard and Move dialog remain) and never scales text below 12px effective. Fix the doc: max 125, or raise it. Slider: `aria-valuetext="{n} percent"`, `step=0.05`, wrapper `role="group"`.

### H-5. Target-size wording is backwards and the real controls are below it
- **Where:** DESIGN.md spacing (`touch-min: 28px`), Layout ("icon buttons on tiles may shrink to touch-min"); `global.css` 1128-1134 (Discovery icon buttons 22px), 486-587 (swatch and priority 18px, popover options 16px with 4px gap), 1076 (card-move 24px), 1059 (delete 26px), 908 (lane pin 26px), `.card-checkbox input` 16px.
- **Problem:** 2.5.8 (WCAG 2.2 AA) needs 24x24 CSS px, or spacing so that a 24px circle around each undersized target does not intersect a neighbour. The 16px popover options 4px apart fail (centers 20px), the 18px swatch and priority 6px apart pass only by touching, and 22px buttons pass only through the spacing exemption. At zoom 0.5 every one of these halves (11px, 9px, 8px). WCAG 2.1 AA has no target rule, but the spine sets a 28px floor and then ratifies smaller values; the wording "may shrink to touch-min" reads as a maximum, not a minimum.
- **Fix:** Reword: "Effective target size at Discovery zoom 100 percent is at least 24x24 CSS px (28 preferred) for every control, including inside popovers; below 0.75 zoom secondary tile controls are not rendered." Set `.discovery-matrix .card-move`, `.drag-handle`, `.card-delete` min 24px, swatch/priority/ticket 24px hit area (padding, not visual size), popover options 28px with 4px gap. Add a computed-style test asserting `getBoundingClientRect` width and height ≥ 24 for every `button, a, input, select, [role=button]` in Playwright.

### H-6. Live updates silently replace unsaved field values and can rearrange under the user; no pause
- **Where:** EXPERIENCE.md Description editor, Interaction Primitives > Live updates, Version conflict; epics 3.10, 3.11; `CardDetailModal.tsx` 33, 146-151 (`useEffect(...,[card])` resets the whole draft and clears `closeConfirm`), `DescriptionEditor.tsx` (`editor.isFocused` guard only).
- **Problem:** The spine guarantees only the Description ("incoming live updates never reset it while it has unsaved text"). Title, Status, Assignee, Estimate, Release, Priority, Color, Business value and Effort are reset by any refetch that yields a new `card` object, and an open "Unsaved changes" dialog is closed. Also the description guard checks editor focus, not dirtiness (focus on the toolbar resets it). 2.2.2 (A) covers automatically updating information that starts automatically: a board that reorders itself on a 2 s cadence needs a way to pause, stop or defer unless deemed essential, and there is none; combined with C-3 a screen-reader or magnifier user loses position.
- **Fix:** Guarantee "no incoming update changes any field that is dirty; the modal shows a callout "This Card changed. Reload / Keep mine" (role=alert) and preserves `closeConfirm`". Add to Live updates: "Hold updates" toggle in the header (default off); while a dialog, popover, Move dialog, drag or text field has focus, board-shape changes are queued and applied on close with one status message. AC: two-client test where the second client edits field X while the first has typed in field Y; both retained.

### H-7. The Discovery grid claim ("row and column headers exposed") cannot be met with the current DOM and hierarchy, and tile semantics are undefined
- **Where:** EXPERIENCE.md Floor bullet 8 (grid with headers; tile name `{Card Key} {level} {title}`), State Patterns > Large map (virtualization); `DiscoveryMatrix.tsx` 314-493 (flat sibling `div`s inside one CSS grid), 827-831 (`aria-hidden` filler cells), `CardTile.tsx` 61 (`<article>`, `<h3>` per tile).
- **Problem:** There are no rows or cells. Column headers are two-level (an Activity spanning N Steps above each Step), which ARIA grid cannot express except with `aria-colspan` on an explicit header row; lane headers are full-width rows. `aria-hidden` filler cells inside a grid break the cell count. A tile name of `{Card Key} {level} {title}` omits state (selected, changed, blocked order, conflict, removed, Release, estimate) and there is no `aria-description` rule, so change markers never reach a screen reader when the user lands on the tile (announcement carries counts only). Each tile is an `<article>` with an `<h3>`; 1,000 headings ruin heading navigation. Virtualization needs `aria-rowcount`, `aria-colcount`, `aria-rowindex`, `aria-colindex`. Glyphs in markers (`+`, `~`, `>`, `-`) are read aloud ("plus New", "tilde Changed").
- **Fix:** Specify the structure in EXPERIENCE.md: `role="grid"` with `aria-rowcount` and `aria-colcount`; header row 1 = Activities (`role="columnheader"`, `aria-colspan`), row 2 = Steps; each lane = `role="row"` with `role="rowheader"` (lane title), each Step-by-Release cell = `role="gridcell"` holding the tile stack; `aria-multiselectable="true"` with `aria-selected` on tiles; remove `aria-hidden` filler cells or mark them `role="presentation"` outside the grid. Tile name stays `{Card Key} {level} {title}` (stable), state goes in `aria-description` (`"Changed by Claude Code. Blocked order behind K-4. Sync conflict."`) and the same text is the visible marker word; marker glyphs `aria-hidden`; drop headings inside tiles (title is a `span`). If `display: contents` rows are used, test on NVDA and VoiceOver. Alternative if this proves brittle: ship a table (`<table>` with `headers`) as the accessible twin like the Graph.

### H-8. Story 6.10 cannot actually gate this: no DOM environment, `--passWithNoTests`, and axe covers a fraction
- **Where:** EXPERIENCE.md Floor intro ("checked by automated axe runs"); epics 6.10 ("axe checks run on their rendered DOM"); `apps/web/package.json` (vitest, no jsdom or happy-dom, no Playwright); AGENTS.md ("Test scripts use `--passWithNoTests`").
- **Problem:** Vitest defaults to the Node environment, so a story writer will add jsdom. jsdom has no layout: axe skips `color-contrast`, `target-size`, `scrollable-region-focusable`, focus-order and `aria-live` timing. axe overall finds only a minority of WCAG failures and none of: focus continuity, keyboard flows, zoom and reflow, live-region behavior, name quality, C-3, C-4. An empty suite passes silently.
- **Fix:** Rewrite the AC of 6.10: run `@axe-core/playwright` in Chromium against the built app on Discovery, Tree, Card modal (open, and with unsaved-changes dialog), Move dialog, one confirm dialog, Graph table, Activity, GitHub Sync, in light and forced-colors emulation, with tags `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag22aa`, `best-practice`; zero violations; the job fails if zero specs run. Add Playwright keyboard specs for: roving grid traversal, Move dialog completion with focus assertion, modal trap and restore (Esc, close button, Back, deep link), live-update status message count, 200 and 400 percent reflow, target-size computed styles, `prefers-reduced-motion`. Add a manual matrix per release: NVDA plus Firefox, VoiceOver plus Safari, keyboard-only pass of UJ-1 and UJ-3.

### H-9. Graph canvas: keyboard operation, parity and focus handoff are underspecified
- **Where:** EXPERIENCE.md Component Patterns > Graph canvas, Floor bullet 6; epics 5.x Graph (Story with FR-63).
- **Problem:** "Pan and zoom" and "selecting a Card highlights" need keyboard equivalents (2.1.1); no pointer-gesture rule (2.5.1: pinch or path gestures need single-pointer alternatives). "Accessible equivalent" is claimed but "same information" is not enumerated (edges with direction, blocked list with the open prerequisite, filter results, selection state, Blocked order flag). Toggling canvas and table loses focus and selection unless mirrored. Node order for keyboard is undefined at 200 nodes. Which view is the default and which one carries the accessible name?
- **Fix:** Specify: canvas is `role="application"` only if unavoidable, else a focusable SVG with `role="graphics-document"`, arrow keys pan, `+`/`-` (only while the canvas has focus) zoom, `Tab` cycles nodes in topological then title order, `Enter` selects, highlights carry glyph and text. The table has columns `Card | Depends on | Required by | Blocked order`, sortable, keyboard-operable, and a selection state shared with the canvas. The toggle is an `aria-pressed` button; the canvas is `aria-hidden` and non-focusable while the table is shown. Filters apply to both and announce the resulting count.

## Medium

### M-1. Switch strip semantics
- **Where:** DESIGN.md Components > Switch strip; EXPERIENCE.md Component Patterns > Switch strip, State Patterns (Agent access off, Agent protection on).
- **Problem:** "Three toggles that open the switch settings, not instant flips" is a button that looks and is named like a switch: role, name and state must agree. "Agent protection On uses warning tone" flags a protective state as a warning (mixed semantics for all users, and tone alone marks it). The danger tone for blocked calls is color-only apart from the counter. Pills that change state (from another tab or an agent) are not announced, and a filled or hollow dot vanishes in forced colors.
- **Fix:** Render as buttons named `"Agent access: On. Open switch settings"` with `aria-haspopup="dialog"`; inside settings use real `role="switch"` with `aria-checked`. Keep text `On`/`Off`, drop the tone rule for protection, keep an icon (shield) that changes shape. Announce a switch change made elsewhere through the status region. Dots use `border` plus fill so they differ in forced colors.

### M-2. Forced colors and dark
- **Where:** DESIGN.md Brand & Style (light only), Elevation (hairlines); `global.css` box-shadow hairlines (868, 1034, 1051); swatches and tints as `background`; no `@media (forced-colors)`.
- **Problem:** The primary developer platform is Windows, where forced colors is common. In forced colors, backgrounds are replaced and box-shadows dropped: level tints vanish (badge text remains, keep it mandatory), color swatches turn into plain boxes, pinned-lane hairlines disappear, filled versus hollow dots become identical, `outline` survives. "Light theme only" is fine for 2.1 AA, but `color-scheme` is not declared, so OS dark mode gives an inconsistent native control rendering.
- **Fix:** Add a "Forced colors" subsection: `@media (forced-colors: active)` sets `forced-color-adjust: none` on swatch chips and marker backgrounds while giving them `border: 1px solid CanvasText` and their glyph, replaces box-shadow hairlines with `border-top`, gives tiles `border: 1px solid CanvasText`, uses `Highlight` for the focus outline. Add `color-scheme: light` on `:root` and a Playwright forced-colors screenshot test. Keep the dark-mode Later item.

### M-3. Reduced motion is one bullet for a system with more motion than it lists
- **Where:** EXPERIENCE.md Floor bullet 7, DESIGN.md Brand & Style ("short transitions that show a change landing"); `SortableCardTile` inline `transition`; skeleton loading state.
- **Problem:** "Short highlight fades" is undefined ("short"), the dnd-kit sortable `transition` is inline and ignores the media query, the skeleton (State Patterns > Cold load) may shimmer, drag lift, popover and dialog transitions are unmentioned. 2.3.3 is AAA, but under reduce the spec promises removal.
- **Fix:** "Under `prefers-reduced-motion: reduce`: no CSS animation or transition longer than 0ms except opacity fades of at most 150 ms; dnd-kit `transition` set to `undefined`; skeletons static; the change marker stays as the only cue." Add a global `@media (prefers-reduced-motion: reduce)` rule and a Playwright emulation assertion.

### M-4. Marker and removed-tile contrast are not specified where they render
- **Where:** DESIGN.md Components > Change marker ("on the tile's top edge, 12px text, color of its kind"; removed "struck through and dimmed"), Callouts; EXPERIENCE.md Change marker; `global.css` 464-467 (`.bulk-selected` overrides the tile background).
- **Problem:** The marker has no background token, so text straddles the tile edge and two backgrounds; `removed` is 4.52 on the activity tint; "dimmed" has no value (at 60 percent opacity the tile text is 3.28); pulse highlights change the background mid-fade; `bulk-selected` replaces the level tint (level identity lost on selection, badge text remains). Blocker: none of these are checked by the "verified on white" statement.
- **Fix:** Give markers an opaque `surface` pill (`background: #FFFFFF; border: 1px solid currentColor`) so contrast is always on white (values 5.64 to 7.41). Specify dimming as `opacity: 1` with `color: text-muted` and a dashed border plus the strike-through, never opacity below 0.9. Pulse animates outline or a left bar, not the background. Bulk-selected keeps the level tint and adds the bar.

### M-5. Truncation and text-size floor
- **Where:** DESIGN.md Typography ("wrap to three lines and truncate", smallest 12px); `global.css` 803-812 (`line-clamp: 3`), 649-654 (`nowrap` ellipsis), font sizes 0.66 to 0.74rem at lines 504, 535, 585, 689, 1116, 1218, 1326, 2146, 2256, 2347.
- **Problem:** Text-spacing override (1.4.12) with clamped or `nowrap` text loses content; the full title is only in the modal or the accessible name, so a sighted user cannot read it without navigating. `title` tooltips are hover-only (1.4.13). The "raise to 12px" is marked `[ASSUMPTION]` and no story or test owns it.
- **Fix:** Show the full title in a focus and hover popover that is dismissible, hoverable and persistent (1.4.13), or in the grid's side "Selected Card" strip; reserve `nowrap` for numeric columns. Add a stylelint rule `font-size` minimum 0.75rem and assign it to Story 1.1.

### M-6. Bypass, landmarks, headings, page titles and route changes are missing from the Floor
- **Where:** EXPERIENCE.md Floor (absent); `RootLayout.tsx` 66-67 (`<main class="shell">` wraps the whole app including `<aside>`), 118 (`<header>` inside `main`), rail `<nav>` without a label, second `<nav>` for view tabs (`story-map-shell.tsx`); `index.html` static `<title>`.
- **Problem:** No skip link (2.4.1), no per-route document title (2.4.2), no focus or announcement on client-side navigation (`?card` and view tab switches), landmark misuse (banner and complementary nested inside `main`), two unnamed `nav`s, tile headings pollute the outline (H-7).
- **Fix:** Add to the Floor: skip link to the workspace; landmarks `header/banner`, `nav aria-label="Main"`, `nav aria-label="Views"`, one `main`; `document.title = "{Route} - {Story Map} - Agentic Story Mapper"` updated on every route; on route change, focus moves to the page `h1` (`tabindex=-1`) and the title is announced; heading levels: h1 page, h2 panels and modal, no headings in tiles.

### M-7. Bulk selection semantics and bar
- **Where:** EXPERIENCE.md Component Patterns > Bulk action bar, Card tile (checkbox), Keyboard (Space); `BoardToolbar.tsx` 76-112; `CardTile.tsx` 69-72.
- **Problem:** The tile checkbox's name is the Card Key only ("K-12"), with no state on the tile; no `aria-selected` (H-7); the bar appears at 1+ selection, pushes the board down, and announces nothing ("3 selected" is a `<strong>`); its selects have no names; "if any Card conflicts, lists all conflicts and applies nothing" has no announcement or focus target; selection is silently cleared when filters hide Cards (`selectedVisibleIds`).
- **Fix:** Name `"Select K-12, {title}"`; the bar is a `role="region" aria-label="Bulk actions"` with labelled controls and `role="status"` count; focus stays on the tile; a shortcut-free path: `Tab` out of the grid reaches the bar first (DOM order before the board). Conflicts list in an `alert` with focus moved to the list heading. Announce "N hidden selected Cards" when filtering.

### M-8. Popover pattern (color, priority) undefined
- **Where:** EXPERIENCE.md Card color popover ("opens on click or Enter ... closes on Esc"); `CardTile.tsx` 140-201, `global.css` 540-554.
- **Problem:** No `aria-expanded`, `aria-haspopup`, focus entry, arrow-key navigation, outside-click and blur close, focus return, or size floor; absolutely positioned inside an `overflow` scroll container and inside CSS `zoom`, so it is clipped at pinned lanes (`max-height:240px; overflow-y:auto`) and mispositioned at zoom ≠ 1; `Enter` conflict with the grid (C-2); popover options 16px (H-5).
- **Fix:** Specify as a listbox popover: trigger has `aria-haspopup="listbox"` and `aria-expanded`; focus moves to the selected option; arrows move, `Enter` selects and returns focus to the trigger, `Esc` closes and returns focus; render in a portal with `position: fixed` measured after zoom; options at least 28px.

### M-9. Error identification, conflicts and inline validation
- **Where:** EXPERIENCE.md Voice and Tone, State Patterns (Version conflict, Sync conflict, Snapshot failed), Flow 2 failure ("composer names the problem"); `CardDetailModal.tsx` (no `aria-invalid` or description on any field).
- **Problem:** 3.3.1 and 3.3.3 require errors identified in text and associated with the field (`aria-describedby`, `aria-invalid`); the spine defines copy but no association, focus movement or role. "The field stays blocked until resolved" has no accessible representation (a disabled field vanishes from tab order; `aria-disabled` plus reason is needed); Reload and Resubmit focus placement is undefined.
- **Fix:** Add: field errors render adjacent text, `aria-invalid="true"`, `aria-describedby`, and focus moves to the first error on submit; conflict callouts are `role="alert"` and receive focus on the callout heading; blocked field uses `aria-disabled="true"` with `aria-describedby` "Resolve the conflict to edit".

### M-10. Rich-text editor and modal form internals
- **Where:** `DescriptionEditor.tsx`, `CardDetailModal.tsx` 220-223, `global.css` 1606-1609.
- **Problem:** The editor is wrapped in a `<label>` together with a toolbar of unnamed buttons (`B`, `I`, `List`, `H2`; no `aria-pressed`, "H2" is not a name); the contenteditable has `outline: none` (C-1) and needs an explicit `aria-label` and multiline role; toolbar arrow-key behavior undefined. The spine requires none of this and promises the editor without listing its keyboard model.
- **Fix:** `role="toolbar"` with named, `aria-pressed` buttons ("Bold", "Italic", "Bullet list", "Heading 2"), editor `aria-label="Description"` `aria-multiline="true"`, visible focus on the frame via `:focus-within`, and a documented Esc behavior (does not close the modal while the editor is focused with unsaved text; closes via Esc only when the user first leaves the editor).

## Low

### L-1. Level identity inconsistent between views
Tree levels use green for Activity, blue for Step, amber for Story (`global.css` 694-696), while Discovery uses blue, amber and white. Consistent Identification (3.2.4) and cognitive load. Fix: one token set for both, referenced in DESIGN.md.

### L-2. Lane header controls
`aria-pressed` and `aria-expanded` are both set on the collapse button and the pin button's `title` flips text with `aria-pressed` (double negation); disabled up/down arrows leave the tab order with no explanation; inline rename commits on blur. Fix: collapse uses only `aria-expanded`; pin uses stable name plus `aria-pressed`; disabled arrows use `aria-disabled` plus reason; rename commits on Enter, cancels on Esc, blur keeps draft.

### L-3. German strings and mixed language
German labels remain until Story 1.1 (`Farbkategorie wählen`, `Priorität wählen`, `GitHub-Ticket erstellen`, `Ungespeicherte Änderungen`, `API nicht erreichbar`) and violate 3.1.2 (language of parts) and 2.5.3 (label in name) in the interim. Fix: add a lint or grep check for non-ASCII German words in the string-module story's AC; fail if `lang="en"` text contains those.

### L-4. Existing banner role conflict
`role="alert" aria-live="polite"` on the API banner (`RootLayout.tsx` 189) contradicts itself. Fix: `role="alert"` only, and the reconnecting rule from C-5.

### L-5. "Do not rely on hover" is not testable
DESIGN.md Do's and Don'ts and EXPERIENCE.md Banned list. Many controls use `title` for their only description (lane pin, add-tile). Fix: AC "no information or action is available only through `title` or hover; a tooltip, when present, opens on focus too, is dismissible with Esc and hoverable (1.4.13)".
